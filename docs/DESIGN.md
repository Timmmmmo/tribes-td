这份文档记录「为什么这么做」，而不是「做了什么」。做了什么看 README。

## 一、三改三不改

移植这件事最容易犯的错，是把「机制」和「结构」混为一谈。
机制是玩家的决策空间，结构是承载决策的外壳。壳可以换，机制不能丢。

### 必须保留的三个机制

**1. 双资源，且不可兑换**

原版同时跑两套资源：金币（造塔、升档内等级）和功勋（跨档解锁建筑形态）。
两套资源不互通，也不存在「用钱买功勋」的捷径。

这个设计产生了塔防里罕见的**双目标取舍**：
- 铺塔保命（花金币）vs 攒钱等质变（不花）
- 升档提上限（花功勋）vs 存功勋买救场技能（不花）

普通塔防只有一个决策轴（钱够了就买），这张图有两个。**这是它最值钱的地方。**

**2. 击杀归属：功勋只算防御单位自己打死的**

原版里召唤物打死怪不给功勋。这不是 bug，是核心规则。

它的作用是**把「靠技能过关」这条路变贵**：
技能能救场，但不产生成长。你越依赖技能，越长得慢。
这条规则让「操作」和「投资」互为代价，而不是互补。

本项目用 `MeritSystem.sync_kills()` 只读 `TDTower.kills` 实现；
主动技能「裁决」直接调 `TDEnemy.take_damage()`，绕开 tower.kills，所以不计功勋。
**代码路径本身保证了这条规则，不靠文档提醒。**

**3. 阶梯价位，不留中间态**

原版 16 档价位（100→16000），相邻档之间跳幅不均匀，但每档都是一次质变。

本项目压缩成 7 档（40/90/190/400/850/1800/3800），但保留「每档 ×2 以上」的跳幅。

为什么这个重要：**如果价位是连续的，最优解永远是「把钱花完」**。
只有存在明显的跳档，「攒着」才成为一个理性选择。玩家的决策密度来自不连续。

`tools/gen_content.py` 里有断言：任一档位的价位必须 ≥ 上一档 ×1.9，且每个塔的 cost 必须等于它所属档位的价位。改数值时脚本会直接失败，防止有人在中间塞一个「179 金币的过渡塔」。

### 必须改掉的三个结构

**1. 时长：56 波 → 15 波**

原版一局 40–60 分钟，中途不能停。手游的留存逻辑是「随时能停」。
40 分钟不可中断的局，等于要求玩家清空一个时段。

15 波 / 8–12 分钟，是「地铁上能打完一局」的长度。波次自动流转（`WAVE_GAP = 2.5s`），不做「手动点开始」——手机玩家不想每 30 秒点一次按钮。

**2. 协作：4 人实时分线 → 单人蛇形路**

原版的社交爽点是「各自守一线、共同通关」。但手机端做实时四方的成本是等房、版本同步、掉线重连、社交压力，而且手机上玩家不想对别人负责。

改成**一条蛇形路 + 多个折返段**：一条路在地图上来回穿，意味着同一个塔位能同时覆盖两三段路。这样「位置价值」被放大，一个人的决策复杂度接近四个人分线的总和，但协作成本归零。

**3. 操作：鼠标精度 → 网格吸附 + 预览 + 预演**

这是技术风险最高的一处。塔防里塔位差一格，伤害差 40%，而手指精度远低于鼠标。

本项目做了三件事补偿：
- **网格吸附**：不给自由放置，永远是整格（`TDMap.cell_at`）
- **范围预览**：悬停即画射程圈，两圈叠加（实线 + 半透明粗线）保证低端屏也看得清
- **落子前提示**：`build_block_reason()` 按「档位未解锁 → 人口已满 → 格子非法 → 金币不足」的**优先级**返回单一原因，而不是笼统的「不能建」

最后一条容易被忽略但很关键：玩家卡住时最需要知道的是「我该攒功勋还是攒钱」。给四个原因等于没给。

## 二、为什么用现成的塔防内核，而不是自研

`addons/td_core` 来自 [godot-tower-defense-core-lite](https://github.com/openclawaimac/godot-tower-defense-core-lite)（MIT），**一行没改**。

理由：
1. 塔的索敌策略（FIRST/LAST/STRONGEST/CLOSEST）、溅射、护甲减免、减速叠加、波次 HP 缩放、路径行走 —— 这些是通用件，自研要两周，且必然带 bug。
2. 它自带 54 项 headless 检查，等于给我们一层回归保护。
3. MIT 许可，商用无约束。

**不改它、而是包一层**，是为了保持可升级：上游更新时直接覆盖 `addons/td_core` 即可，我们的改动全在 `game/` 里。

代价是它的 `TDEconomy` 只有单资源（gold）。但这不是问题 —— 功勋是**加法**，不是改造：
`MeritSystem` 独立持有功勋状态，只在需要时读 `TDTower.kills` 和 `TDEconomy`。
两个系统之间只有一条单向依赖，耦合足够低。

## 三、竖屏 720×1280 的推演

三个候选布局：

| 方案 | 地图尺寸 | 问题 |
|---|---|---|
| 横屏 1280×720 | 20×11 格 | 手机上要双手握持，单手玩不了 |
| 竖屏 + 地图横向铺 | 9×15 格 | 路径只能上下走，折返段少，位置价值低 |
| **竖屏 + 蛇形折返** | **9×15 格，13 个航点** | 采纳 |

蛇形路径的 13 个航点让一条路穿过 9 列里的 6 列、15 行里的 13 行，形成 5 个折返。
一个放在折返处的塔能覆盖 3 段路，放在直道只能覆盖 1 段。**位置决策因此有了深度**，这是靠地图结构而非人数堆出来的复杂度。

布局切分：
```
0–150      顶部资源条（金币 / 功勋 / 生命 / 波次 / 人口 / 解锁进度 / 部族切换）
150–1110   棋盘 576×960
1012–1090  选中塔时的操作条（升级 / 出售），浮在棋盘下沿
1100–1196  塔卡片（当前部族最多 7 档）
1200–1272  三个技能按钮
```

HUD 全部自绘 + 手动命中测试，不用 Control 节点树。
原因：元素数量固定、布局固定，自绘能保证视觉一致，也避免嵌套容器的点击穿透问题 —— 手机上「点 UI 结果在地图上造了个塔」是最招骂的 bug 之一。
`handle_input()` 里对 `p.y > CARD_Y` 的兜底就是为这个：底部空白区域吞掉点击，不往下传。

## 四、数值设计

### 七个档位的价位

```
T1   40    铺得起，但打不动
T2   90    第一批主力
T3  190    第一个明显的质变点
T4  400    中期主力
T5  850    后期门槛
T6 1800    终局单位
T7 3800    全清的话只出得起一两个
```

### 六部族的数值指纹

同一个价位，六个部族给出六种不同的「伤害 / 射程 / 攻速 / 溅射 / 减速」组合：

| 部族 | 指纹 | 强势期 | 弱点 |
|---|---|---|---|
| 游侠 | 低伤、高攻速、带减速 | 前中期 | 打不动重甲 |
| 咒术 | 高伤、低攻速、大溅射 | 中期清杂 | 单体乏力，BOSS 波吃亏 |
| 猎手 | 中伤、高射程、对空强 | 全程稳定 | 什么都不突出 |
| 盗贼 | 低伤、击杀额外金币 | 滚雪球 | 前期必须守得住 |
| 狂战 | 短射程、高单伤、强减速 | 卡口 | 位置要求苛刻 |
| 剑咏 | 均衡 + 溅射 | 中期 | 需要和别的部族配对 |

**部族差异不靠「数值高低」，靠「曲线形状」**。同样 400 金币，盗贼和狂战能打出完全不同的局面，玩家换部族等于换一套经济模型 —— 这是重玩价值的来源。

### 数值健康度检查

`tests/run_tests.gd` 里有一项 `dps_per_gold_sanity`：
同部族内，相邻档位的「每金币 DPS」偏离不得超过 3 倍。

理由：如果某一档的性价比压倒性领先，玩家就会永远停在那一档，后面四档形同虚设，阶梯设计就失效了。这项检查是在防「数值单一解」。

## 五、还没解决的问题

1. **毒 / 弹射 / 眩晕没有真机制。** td_core 只提供伤害/攻速/射程/溅射/减速/对空六个维度。
   本切片用组合近似，代价是「游侠的毒」和「狂战的减速」在体感上区分度不够。
   真要做，需要给 `TDEnemy` 加 DOT 队列和状态机（见 ROADMAP 迭代二）。
2. **BOSS 波没有专属机制。** 现在 BOSS 只是一个高血高甲的大怪。
   原版的 BOSS 有阶段转换和技能，这是「决战期」的爽点来源，缺了它，第 15 波和前 14 波没有本质区别。
3. **没有局外成长。** 现在一局结束就什么都没了。手机端的留存靠局外养成和每日目标，这是迭代三的事。
4. **难度只有一档。** 原版有简单/普通/困难/天才 + 灾厄/大灾变。没有难度阶梯，核心玩家三天就玩完了。
