# 迭代路线

## 迭代一 · 机制闭环（本次交付）

目标：证明「双资源 + 六部族 + 阶梯价位」在 Godot 上跑得通，且手机端操作可用。

- [x] 塔防内核接入（MIT 上游，未改动）
- [x] 功勋系统：击杀归属、档位解锁、人口、三个主动技能
- [x] 32 个防御单位 / 6 部族 / 7 档阶梯价位
- [x] 15 波关卡、5 种敌人（含 BOSS）
- [x] 竖屏 HUD（自绘 + 手动命中测试）
- [x] 建造预览：网格吸附 / 射程圈 / 落子前的原因提示
- [x] headless 自测（覆盖本项目独有机制）
- [ ] **运行时验证 —— 待你在装了 Godot 的机器上跑一次**

**出口标准**：能在手机上完整打完 15 波，且「3 秒内完成一次精准造塔」。

---

## 迭代二 · 机制补齐（约 2 周）

这一轮补的是「体感区分度」。现在六个部族只在数值曲线上不同，玩家三局之后会觉得是同一个游戏。

- [ ] `TDEnemy` 加状态机：DOT 队列（毒 / 灼烧）、眩晕（完全停止）、击退（路径回退）
- [ ] `TDTower` 加弹射（chain）：命中后向最近目标跳一次，伤害衰减 40%
- [ ] `TDTower` 加朝向：猎手系只在朝向锥形内开火（原版机制）
- [ ] 召唤物系统：能造成伤害，但**不进入 tower.kills**（直接复用现有规则，天然合规）
- [ ] BOSS 阶段转换：血量 70% / 40% 时切换技能，打破「一直点」的节奏
- [ ] 第二张地图（双入口分叉）、第三张地图（单条长廊，考考验极限）

**出口标准**：六个部族各打三局，玩家能说出「玩法不一样」而不是「数值不一样」。

---

## 迭代三 · 留存结构（约 6–8 周）

这一轮才碰商业化。在机制没打透之前做养成，等于给一个不好玩的游戏加长留存曲线，是把问题往后推。

- [ ] 局外养成：六条职业线，各自的图腾收集（原版的「集齐一套图腾给全局加成」）
- [ ] 存档与云同步（本地存档先做，云同步随账号系统）
- [ ] 难度阶梯：简单 / 普通 / 困难 / 天才，用 `hp_scale_per_wave` + 出生金币区分
- [ ] 每日目标 + 周常挑战（用现有波次数据组合，不新增内容）
- [ ] 异步 PvP：用别人的防守阵容当关卡，排行榜
- [ ] 新手引导：前 3 波强制教学，重点教「双资源」这一件事

**出口标准**：次日留存能上 30%（塔防品类的中位线），7 日留存 8% 以上。

---

## 迭代四 · 商业化与合规（视数据决定）

- [ ] 广告位：复活 / 加速 / 双倍奖励（塔防的广告容忍度高于抽卡）
- [ ] 内购：部族解锁（内容型）+ 皮肤（外观型），**不做数值售卖**
- [ ] 世界观重做：原版的「人族 / 雅典娜 / 魑魅魍魉」属于暴雪 IP 与原作者，必须全部替换
- [ ] 隐私合规：安卓权限、SDK 清单、未成年人保护
- [ ] 性能目标：中低端机（骁龙 660 级）稳定 60fps，包体 < 80MB

**红线**：世界观与美术在商业化前必须 100% 重做。机制可以借鉴（不受版权保护），
名称、角色、剧情、美术一个都不能留。

## 已知技术债

| 项 | 位置 | 说明 |
|---|---|---|
| `content.json` 由脚本生成 | `tools/gen_content.py` | 想改数值必须改脚本再重新生成，直接改 JSON 会在下次生成时被覆盖 |
| HUD 全自绘 | `game/hud.gd` | 元素一多会难维护；超过 ~40 个可交互元素就该换回 Control 树 |
| 单位渲染在 main 里 | `game/main.gd::_draw_*` | 现在是几十个单位，性能没问题；上到 200+ 时要把单位改成独立 Node2D + 贴图 |
| 无对象池 | `td_core` 的 spawn/remove | 波次间隔短、同屏单位多时会触发 GC 抖动，迭代二再优化 |
| 无存档 | — | 迭代三 |
